# Architecture — GetShortlisted.com

## One-line summary
A fast, static, SEO/GEO-first marketing site (generated by a tiny Node build script) served by **Cloudflare Workers Static Assets**, with one Worker API endpoint that saves leads into **Cloudflare D1** and emails the owner through **Cloudflare Email Routing**.

```
                 ┌──────────────────────────── Cloudflare ────────────────────────────┐
 Visitor ──HTTPS──►  getshortlisted.com                                            │
                 │     │                                                              │
                 │     ├─ /, /blog/…, /faq/ …  ──► Static Assets (./public)  (no code runs, edge-cached)
                 │     │                                                              │
                 │     └─ /api/*  ──► Worker (src/worker.js)                          │
                 │                    │  POST /api/lead                               │
                 │                    ├─ validate + honeypot + same-origin + rate limit
                 │                    ├─ INSERT ─► D1 database "getrecruitercalls-db" (table: leads)
                 │                    └─ send_email ─► Email Routing ─► nishit.salian02@gmail.com
                 └────────────────────────────────────────────────────────────────────┘
```

## Page model
Each page is a plain object rendered by `layout.mjs → render(page)`:

| Field | Purpose |
|---|---|
| `path` | URL with trailing slash, e.g. `/faq/` (becomes `public/faq/index.html`) |
| `title`, `description` | `<title>` and meta description (build fails if missing). Suffix `| GetShortlisted` is added only if total ≤ 65 chars |
| `body` | Page HTML |
| `schema` | Extra JSON-LD nodes (Organization + WebSite are always included) |
| `keywords`, `priority`, `changefreq` | sitemap + meta |
| `noindex` | Excludes from sitemap, adds `noindex` |
| `ogType`, `published`, `modified` | Article metadata |

**Add a new page:** create/extend a module in `site/pages/`, export the page object, run `npm run build`. The sitemap updates automatically. Also add it to `site/static/llms.txt` and (if important) the footer/nav in `layout.mjs`.

## SEO & GEO (Generative Engine Optimization) features
- Static HTML: every word is in the HTML — no JavaScript needed to read content (best for Google *and* AI crawlers).
- Unique `<title>`, meta description, canonical URL, single H1 per page (enforced by tests).
- Open Graph + Twitter cards with a 1200×630 share image.
- JSON-LD `@graph` on every page: `Organization`+`ProfessionalService`, `WebSite`, plus per page `Service`, `FAQPage`, `Article`, `BreadcrumbList`, `AboutPage`, `ContactPage`, `CollectionPage`.
- "Quick answer" boxes at the top of guides + question-style H2s + FAQ blocks — the format AI answer engines quote.
- `robots.txt` explicitly allows Googlebot, Bingbot, GPTBot, OAI-SearchBot, ClaudeBot, PerplexityBot, Google-Extended etc.
- `llms.txt` — plain-language summary of the business for LLMs.
- `sitemap.xml` generated from page list with lastmod.
- Fast: no framework, ~12 KB CSS+JS, long-cache headers, fonts with `display=swap`.
- Accessibility: skip link, labels on every field, focus styles, `aria-live` form status, reduced-motion support.

## Lead flow (POST /api/lead)
1. Browser JS validates (name, 10-digit Indian mobile, email, at least one of Naukri/resume link, experience) and posts `application/x-www-form-urlencoded` with `Accept: application/json`.
   Without JS, the form still posts normally and the Worker answers with a 303 redirect to `/thank-you/` (or `/contact/?error=1`).
2. Worker checks: same-origin `Origin` header, honeypot field `company_website` (bots get fake success, nothing saved), server-side validation (same rules), max **5 leads per IP per hour** (IP stored only as salted SHA-256 hash).
3. Lead inserted into D1 `leads` table.
4. `ctx.waitUntil` sends the notification email (HTML + text, Reply-To = candidate, WhatsApp button) and then sets `email_status` = `sent` / `failed` / `skipped`.
   If the email fails, the lead is still safe in D1.

### D1 table `leads`
`id, created_at (UTC ISO), name, phone, email, naukri_url, resume_url, experience, target_role, message, source_page, utm_source, utm_medium, utm_campaign, ip_hash, user_agent, email_status`

## Configuration
| Where | What |
|---|---|
| `site/config.mjs` | Brand name, URL, founder, public email, social links, `updated` date |
| `wrangler.jsonc → vars` | `NOTIFY_TO` (owner Gmail), `NOTIFY_FROM` (sender on our domain), `SITE_URL` |
| `wrangler.jsonc → send_email.destination_address` | Must equal `NOTIFY_TO` and be a **verified** Email Routing destination |
| `wrangler.jsonc → d1_databases.database_id` | Paste the id from `wrangler d1 create` |
| `site/static/css/styles.css :root` | Brand colors |

## Why these choices
- **Workers Static Assets instead of Pages**: Cloudflare's recommended path; static files are free & unlimited, Worker runs only for `/api/*`.
- **No framework / no npm dependencies at runtime**: nothing to break or update, perfect Lighthouse scores, content fully crawlable.
- **Email Routing `send_email`** instead of a third-party email API: free, no API key, but it can only send to *verified* addresses (fine — notifications go to the owner only).
- **D1** keeps every lead even if Gmail misses an email; query anytime with `npm run leads:remote`.
